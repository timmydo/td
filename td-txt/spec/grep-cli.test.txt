# grep — the option surface, exit statuses and diagnostics.
#
# td-txt-authored (see spec/README): the vendored GNU suites cover the REGEX
# engine and assert only an exit status, so everything about grep as a PROGRAM —
# which lines it prints, how it prefixes them, what it exits with, what it
# refuses — lives here. Goldens were produced by running each case against GNU
# grep 3.11 under LC_ALL=C.

#### a matching pattern selects the line and exits 0
## argv: grep apple
## stdin:
apple
banana
cherry
apple pie
## END
## stdout:
apple
apple pie
## END
## status: 0

# The eat reads that same state, so an ASSERTION re-arms it for the whole run of
# braces behind it rather than only the one it touches. A first draft routed the
# eat through `first`, which cannot be re-established, and these four are what
# showed it.

#### an assertion re-arms the eat for the braces behind it, not just the first
## argv: grep -c -E '(a\b{{*)'
## stdin-json: "a{{\na\n"
## stdout-json: ""
## stderr-contains: Unmatched ( or \(
## status: 2


#### with no operator to carry either
## argv: grep -c -E '(a\b{{)'
## stdin-json: "a{{\na\n"
## stdout-json: ""
## stderr-contains: Unmatched ( or \(
## status: 2


#### and an interval between them does not survive the assertion
## argv: grep -c -E '(\b{2}\b{{*)'
## stdin-json: "a{{\na\n"
## stdout-json: ""
## stderr-contains: Unmatched ( or \(
## status: 2


#### where without the assertion there is nothing to re-arm it
## argv: grep -c -E '(a{{*)'
## stdin-json: "a{{\na\n"
## stdout-json: "1\n"
## status: 0
